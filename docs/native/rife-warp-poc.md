# RIFE Warp Compatibility PoC

Validation date: 2026-08-11

## Scope

This Phase C4.6 proof of concept validates the official RIFE custom Warp layer
against the independently built ncnn 20250503 Vulkan package. The PoC is kept
outside GVFI at `D:\GVFI-deps\rife-warp-poc`.

No GVFI runtime code, Native Backend, production CLI, ncnn source, or RIFE model
file was changed.

## Warp implementation

`Warp` inherits `ncnn::Layer`. The official source provides:

- a CPU bilinear-sampling forward implementation;
- Vulkan pack-1, pack-4, and pack-8 forward shaders;
- Vulkan pipeline creation and destruction;
- the `Warp_layer_creator` generated by `DEFINE_LAYER_CREATOR(Warp)`.

The PoC registers the layer before loading the graph:

```cpp
net.register_custom_layer("rife.Warp", Warp_layer_creator);
```

The CPU implementation compiled and linked but was not separately executed.
The runtime test explicitly used `VkMat`, `VkCompute`, and the Vulkan extractor
overload, so the Vulkan custom-layer path was exercised.

## Compatibility findings and limits

The official 20221029 Warp source compiles without source changes against ncnn
20250503. Its layer registration, shader compilation, Vulkan pipeline, model
loading, and FP32 Vulkan forward are compatible on the tested GPU.

An earlier harness attempt enabled the production-style FP16 storage and INT8
storage options while directly uploading FP32 tensors. It produced non-finite
output because that configuration normally relies on the separate official
`rife_preproc` shader to convert RGB8 input and normalize it. The PoC therefore
isolated Warp compatibility with a valid normalized FP32 input path. It does
not claim validation of the complete production preprocessing/postprocessing
pipeline, FP16/INT8 path, TTA, UHD mode, image parity, or video integration.

## Conclusion

The compatibility PoC passes. The existing `rife-v4.6` model can be loaded and
executed by ncnn 20250503 Vulkan after registering the official `rife.Warp`
implementation. This proves the missing custom layer can be supplied outside
`rife-ncnn-vulkan.exe`; it does not yet constitute a production Native Backend.
